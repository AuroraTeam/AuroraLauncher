# Запуск и инициализация сервера

## Инициализация

Создание `new LauncherServer()` не запускает сервер. Точка входа вызывает
`await server.start()` и обрабатывает ошибку запуска с кодом завершения 1.
Повторные вызовы `start()` возвращают тот же Promise; перезапуск остановленного
экземпляра не предусмотрен.

Порядок запуска:

1. Чтение конфигурации, аргументов и регистрация провайдера авторизации.
2. Ожидание `ProfilesManager.init()` и `ClientsManager.init()`.
3. Ожидание `WebServerManager.init()`, включая чтение TLS-сертификата и ключа.
4. Регистрация команд и HTTP-маршрутов без запуска консоли и Watcher.
5. Ожидание HTTP `listen()`, затем готовности Watcher и включение консоли.

Проверка обновлений запускается после подготовки сервера и не блокирует запуск.
Ошибка этой проверки записывается в журнал. При ошибке обязательной инициализации
закрываются уже созданные HTTP-сервер, Watcher и консоль. Для освобождения этих
ресурсов также доступен `await server.stop()`.

## Остановка

Команда `stop`, Ctrl+C в консоли, `SIGINT` и `SIGTERM` используют один путь
асинхронной остановки. Команды получают callback через `ShutdownToken`, без
зависимости от конкретного экземпляра `LauncherServer`.

Повторные и одновременные вызовы `stop()` возвращают один Promise: ресурсы
закрываются один раз. Если остановка запрошена во время запуска, сервер ждёт
завершения текущей операции инициализации и пропускает дальнейшие этапы.
Вызов `start()` после остановки до начала запуска отклоняется.

Остановка закрывает консоль, обе подписки Watcher и HTTP-сервер, а также отменяет
фоновый HTTP-запрос проверки обновлений. Остановленный Watcher нельзя включить
обратно из завершающейся команды загрузки. Уже начатые команды загрузки при этом
не отменяются автоматически.

Ошибка освобождения одного ресурса не мешает попытке закрыть остальные.
Ошибки собираются в `AggregateError`; для команды и сигналов устанавливается
код завершения 1. При ошибке самого запуска сохраняется исходная причина ошибки,
а ошибки последующей очистки дополнительно записываются в журнал.
Штатная остановка освобождает ресурсы без принудительного `process.exit()`.

## Проверки

Из корня репозитория:

```sh
pnpm --filter @aurora-launcher/server test
pnpm --filter @aurora-launcher/server typecheck
pnpm --filter @aurora-launcher/server build
```

Тесты запуска используют встроенный `node:test` и транспилируют реальные классы
через TypeScript. Внешние сервисы и ввод-вывод заменены заглушками: проверяются
ожидание этапов, обработка ошибок, остановка во время запуска, повторная
остановка, сигналы процесса и освобождение ресурсов. Проверки Forge/NeoForge
покрывают отсутствующие данные установщика и объединение библиотек Log4j.
Сетевые запросы и подключения к БД в unit-тестах не выполняются.
